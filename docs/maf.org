** bindings
   three binding modes:
   1) calc-native bindings
      - this set of mappings tries to stay as close as possible to the default calc bindings
      - if a user familiar with calc uses maf, they should be instantly familiar
        and should not have to re-adjust to new bindings
      - rules:
        - use the default calc bindings
        - never displace a calc binding for convenience (the defining contrast
          with mode 2)
        - rebind existing combinations with their maf- siblings
          - eg, `+` is rebound from calc-add to maf-add
        - maf commands with no calc sibling are simply not bound
          - this mode is for those who strictly want to work comfortably in
            vanilla calc while still getting maf's improvements to the commands
            they already know
          - users who want the new commands can bind them manually
   2) maf-native bindings
      - this is the opinionated set of bindings optimized for maf
      - this is the default activated bindings for maf
      - starts from the default calc bindings, but unlike (1) displaces a calc
        binding whenever it pays — that one contrast is the entire difference
        between the two modes
      - uses emacs-style navigation (C-n, C-p, M-f, M-b) for basic navigation
   3) vim-flavored bindings
      - "flavored", not "-native": we're not emulating vim's command model,
        just borrowing a few keys for navigational convenience
      - this is similar to (2), but instead prefers vim-style bindings for navigation
      - so `hjkl` and `wb` are taken up solely for basic navigation
      - we overwrite all of these keys; everything currently on them needs a new
        home. what each stolen key holds today (in maf-native):
        - `h` — calc-help-prefix (the whole h help family)
        - `j` — the selection prefix, close to maf's core:
          - maf's own: mafcmd-raise (j j), mafcmd-isolate (j i),
            mafcmd-unpack (j U), maf-merge (j M), maf-distribute (j D),
            maf-jump-equals (j e), maf-commute-left/right (j l / j r)
          - calc's selection machinery: calc-select-here/once/more/less/
            next/previous/part, calc-sel-add/sub/mult/div-both-sides,
            calc-sel-isolate/commute/distribute/merge/negate/invert/
            evaluate/expand-formula, calc-rewrite-selection,
            calc-enter/edit/copy/del-selection,
            calc-enable/show/clear/break-selections, calc-unselect,
            calc-conj
        - `k` — the combinatorics prefix:
          - mafcmd siblings shadowing calc: choose, gcd, lcm, prfac,
            nextprime, totient, moebius, euler, bern, random, shuffle,
            utpt/utpp/utpc
          - maf-only: mafcmd-evaluate (k k), mafcmd-complete-square (k s),
            mafcmd-factor-powers (k d)
          - calc-only leftovers: calc-keep-args (k K), calc-prime-test,
            calc-random-again, calc-extended-gcd, calc-utpn/utpf/utpb
        - `l` — maf's own invented prefix, layered over calc's log-units
          prefix:
          - maf's own: mafcmd-factor-by (l f), mafcmd-factor-gcd (l F),
            mafcmd-collect-fractions (l t), mafcmd-float (l l),
            mafcmd-frac (l c), mafcmd-to-degrees (l d),
            mafcmd-to-radians (l r), mafcmd-inverse-function (l v),
            mafcmd-swap-vars (l x), mafcmd-unique-groups (l g)
          - calc's log-units family: calc-lu-plus/minus/times/divide/quant,
            calc-db, calc-np, calc-freq, calc-midi, calc-spn
        - `w` — calc-why (single command)
        - `b` — the binary/financial prefix:
          - mafcmd table rows: and, or, xor, diff, not, clip, lsh, rsh,
            ash, rash, rot, vpack, vunpack, irr, npv, relch
          - calc-only: calc-word-size (b w), calc-percent-change,
            calc-log (b B), calc-lshift/rshift-arith,
            calc-fin-pv/fv/pmt/nper/rate/sln/syd/ddb
   open decisions:
   - how a mode is chosen, and whether it can be switched live
     - defcustom? a command? what happens to a user's own overrides on switch?
   - where the per-mode keys live
     - the mafcmd table currently binds keys from row data (one key per row),
       and bindings.el collects everything made outside the table
     - three modes means either extra key columns in the table (defaulting to
       the maf-native key when they'd be identical), or three separate override
       layers on top of one base map
     - picking this early matters: it's also the maintenance answer to the real
       cost of this feature — every future command needs a key decision × 3
   - mode 1's navigation story
     - mode 2 names C-n/C-p/M-f/M-b; mode 1 is silent. is that "whatever emacs
       does globally", or deliberately no navigation bindings? record whichever
       it is
