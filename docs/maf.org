* PORT:stack.el
** Motion
   Already covered: forward/backward noun → =maf-forward-noun= /
   =maf-backward-noun= (M-f/M-b). Every number, variable and function
   name is a stop — the name lands point on the call it heads — and the
   operators and the line-number prefix are what the motion crosses, the
   latter the line-prefix bug, fixed with the port.
** Triangles
   - [X] calcFunc-hypot advice — symbolic args: sqrt(abssqr(a) + abssqr(b)).
     Ported as behavior, not as advice: =mafcmd-hypot= (f h) applies maf's
     own =maf--hypot=, which squares under a structural math-normalize the
     way =maf--cath= already did — so no abssqr, and nothing advises calc's
     own =calcFunc-hypot=. It also answers where the legacy advice still
     gave up: hypot(a, b) is sqrt(a^2 + b^2), a formula that composes,
     where the advice handed back the inert call. =maf--pythagoras= is now
     the shared step, hypot the plus direction and cath the minus, and
     they are each other's Inverse variant (I f h, I f l). Complex legs
     are the one case calc's own reads better — abssqr takes a modulus,
     squaring does not. Tests: =tests/hypot.el=.
   - [ ] Renormalized :arg forfeits exactness — =maf--resolve-context= takes
     :arg as (math-normalize (calc-top 1 'full)), and the stack top is
     already normal, so the extra pass only floats an exact sqrt(2) into
     1.41421356237. Every binary command is affected: 2 with sqrt(2) under
     f l gives 1.41421356238 rather than sqrt(2), and f h with two radical
     legs gives 2. rather than 2. Pinned in =tests/hypot.el=, which asserts
     the float so a fix trips the line.

  - [X] my/calc-edit-square-dwim / -cube-dwim (:) — insert ^2; repeats increment.
    One key, not three: W and \" were the same command twice over, and
    ^3 is M-3.
  - [-] Power shortcuts (M-2..M-9) — insert ^n. M-' (^()) not ported.
  - [X] my/calc-edit-toggle-brackets (S-up/down) — =maf-editplus-toggle-brackets=.
    Both ends move together, except on an interval, where =[= and =(=
    are values (included / excluded) and the end point is at moves
    alone. The legacy always retyped the one character under point,
    which mismatches an ordinary group. Works from inside the group
    too, not only with point parked on a delimiter.
