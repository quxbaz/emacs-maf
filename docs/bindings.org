#+title: bindings module plan

* concepts
  - the `maf-bindings` module controls whether maf bindings are active at all
  - a *profile* selects the key layout: `calc`, `native` (default), `vim`
  - the bindings are what's native, not the commands: every profile runs
    mafcmds — the calc profile means calc's *layout*, maf's *commands*

* architecture: hub and spokes
  - one shared *base map*; each profile map is an independent sibling
    inheriting from base — no profile references another profile's
    *map*. The one sanctioned relationship is *derivation*, resolved
    at compile time: a profile registered with :derive compiles the
    source's effective defaults beneath its own declarations, an own
    claim displacing whatever it overlaps (vim derives from native
    this way). The compiled maps stay independent siblings
  - base holds *command remaps only*, so it claims no keys and cannot
    collide with any profile's layout:
    #+begin_src elisp
      (define-key maf-bindings-base-map [remap calc-plus] #'mafcmd-add)
    #+end_src
  - remaps are audited (allowlist), not automatic: maf deliberately keeps
    some calc originals reachable as escape hatches (j E vs j e), and a
    remap would silently convert them. Excluding from the allowlist *is*
    the escape hatch — no wrapper commands
  - beneath base sits the *escape map*, base's parent: the keys that
    exist in every profile and even with the module off. It holds one —
    `m c`, the module menu (`maf-list-modules`) — the deliberate
    exception to the calc profile's untouched-layout promise and to
    off's zero keys, because that buffer is where profiles and modules
    are turned back on; anywhere less durable and the way back is M-x
    by name
  - profile deltas are declared, and a declaration may target several
    profiles (source-level sharing); a profile that is another plus a
    delta says so once with :derive instead of every declaration
    naming it:
    #+begin_src elisp
      (maf-bindings-define '(calc native) "x" #'mafcmd-expand)
      (maf-bindings-defprofile 'vim :derive 'native)
      (maf-bindings-define '(vim) "w" #'maf-forward-noun)
    #+end_src
  - `maf-mode-map` stays the one registered map (stable dispatcher);
    switching = repointing its parent, live, nothing rebuilt:
    #+begin_src elisp
      (maf-bindings-set-profile 'calc)
    #+end_src

* lookup order (per profile)
  1. user bindings (per-profile user map first, then the common user map)
  2. enabled-module declarations
  3. profile defaults (minus compiled suppressions)
  4. base remaps
  5. the escape map (`m c`, the module menu) — also the *whole* map
     while the module is off
  6. calc's own map

* user configuration
  - user maps are never written or rebuilt by maf; they survive
    switches. Named maf-<profile>-user-map — `maf-calc-user-map`,
    `maf-native-user-map`, `maf-vim-user-map`, `maf-common-user-map` —
    and defprofile generates the name for a custom profile
    (maf-my-dvorak-user-map). Internal generated maps keep the long
    `maf-bindings-` names
    #+begin_src elisp
      (setq maf-bindings-profile 'vim)   ; before maf loads;
      ;; after load: M-x maf-bindings-set-profile, or customize
      (define-key maf-vim-user-map (kbd "g") #'maf-go-home)
      (define-key maf-common-user-map (kbd "<f6>") #'maf-history)
    #+end_src
  - principle: the user surface is plain elisp — real keymaps,
    `define-key`, `kbd` — for everything a keymap can express: adding,
    moving, overriding
  - the one exception is removal, which no keymap entry can say (nil
    exposes what lies below, `undefined` blocks calc too, and a sentinel
    command in the user map would shadow the fall-through it promises).
    So removal is the one API call:
    #+begin_src elisp
      (maf-bindings-unbind 'native ">")  ; > falls through to calc
    #+end_src
    suppressions live in the registry; the compiler omits the default
    from the generated map, so lookup falls through naturally, C-h k
    names the effective lower command (calc's own, or the maf sibling
    where a base remap applies), and the call itself triggers the
    recompile. `maf-bindings-restore` is the inverse — it drops the
    suppression and the profile default returns. Scope: suppression removes *generated key declarations*
    — profile defaults and module declarations alike, for that profile;
    a suppressed prefix key (j) removes every generated descendant and
    exposes calc's whole prefix. Base remaps are not key declarations
    and still apply: suppression exposes calc's *layout*, but a calc
    command with a maf sibling still runs the sibling — suppressing +
    can never produce raw calc-plus
  - users can declare their own profiles — a profile is just a
    registered name plus two maps over base, nothing about the built-in
    three is special:
    #+begin_src elisp
      (maf-bindings-defprofile 'my-dvorak :clone 'native)
      (maf-bindings-define '(my-dvorak) "n" #'mafcmd-solve)
      (maf-bindings-set-profile 'my-dvorak)
    #+end_src
    tweaks to an existing profile don't need this — that's the user
    map's job; a profile earns its existence as a whole switchable
    layout
  - clone copies the source profile's *own defaults only*, at the
    declaration level; module keys are never copied — they follow the
    module's own targeting, live
  - ships after the built-ins work: custom profiles need the
    profile-aware displays, so both land together

* migrating an init
  - a direct `(define-key maf-mode-map ...)` in an init still works —
    the map's own entries outrank the parent composition — but it is
    outside the system: it survives profile switches indiscriminately
    and suppression cannot see it. Move it to the profile's user map
    (or `maf-common-user-map`):
    #+begin_src elisp
      ;; before                                  after
      (define-key maf-mode-map (kbd "g") #'maf-go-home)
      (define-key maf-native-user-map (kbd "g") #'maf-go-home)
    #+end_src

* rules
  - dogfooding: the built-in profiles are declared through the same
    public API a user would use — `maf-bindings-defprofile` +
    `maf-bindings-define`, no privileged internal path. The built-ins
    are ordinary registry entries that happen to ship with maf, and
    double as the reference example for writing your own
  - modules declare their keys to the binding system; no raw define-key
    into `maf-mode-map` (a toggle must never erase a user override).
    Module targets are explicit profile names, `:all` deliberately —
    strictness governs modules too: under strict, the calc profile gets
    no direct module key declarations, though a module command that is
    a genuine calc sibling may still arrive as a remap (audited like
    base remaps — an escape-hatch original is a reason not to); under
    curated additions, also keys that displace nothing (options' ?
    shadows calc-help, so not there either way). Follows the strictness
    ruling below
  - registrations are owned and replaced as whole sets, so a reload is
    safe by construction: defprofile replaces that profile's default
    set, a module registration replaces that module's set, generated
    maps rebuild from the registry — a declaration deleted from source
    is gone after reload. User maps are never rebuilt
  - profiles govern the stack map and the digit-map overrides only;
    maf-edit, history, formulas, options keep their own fixed maps
  - digit-map changes are tracked installs: each declaration names the
    stock calc binding it expects to replace; install only when the
    current binding equals it (a user's direct customization is left
    untouched), save it, and uninstall restores it only if the current
    binding is still the one maf installed
  - key displays (module help, dial legends) derive keys from the active
    profile — no static key strings
  - the *maf-modules* row for maf-bindings files under the menu's
    Prefs group and is a profile picker, not a toggle: `off | calc | native | vim | ...` with the user's custom
    profiles listed too (they appear when the menu opens). off is the
    module off — stock calc, no maf keys but the escape map's `m c`,
    the way back to this menu
  - the registry compiler validates at build time: a key cannot be both
    a command and a live prefix in one profile; module/profile and
    module/module key conflicts are errors, not precedence accidents

* calc profile
  - promise: zero surprises for a calc user; layout untouched. The one
    exception is the escape map's `m c` (unbound in calc itself) —
    every profile carries it, this one included
  - siblings run via base remaps on calc's own keys (+, a x, a S, ...)
  - keys whose calc command has no sibling stay calc's (x, h, scrolling)
  - no navigation bindings: silence means stock calc/emacs lookup

* profile:native
  What today's layout is, beyond calc's own keys. The shadowing and
  additions groups below are declared `'(native)` — src/bindings.el is
  the native layout's file. calc and vim carry only the sibling groups
  (and, pending the module strictness ruling, the module keys); vim
  stays identical to calc until its content phase lays it out.

  Policy (2026-08-19): `k` and `l` are native's custom-command
  prefixes. A maf command may take a weak key there without a thematic
  case — `k s` complete-square and `k d` factor-powers are such claims
  — and new custom bindings reach for these two prefixes first. The
  sitting residents (combinatorics siblings under k, log-units under
  l) keep their stock keys until a custom command actually claims one:
  eviction is lazy, per key, never a sweep. The bulk first:
  - the mafcmd table: ~200 contextual siblings shadowing their calc
    originals on calc's own keys (the key column in src/maf-cmds.el)
  - base remaps: undo, undo-redo, calc-undo, calc-redo → maf-undo/redo
  - the escape map beneath base: `m c` maf-list-modules — in every
    profile and with the module off, not a native addition
  - module keys: `SPC` \` `C-o` `(` (edit), `?` (options), `t d` `M-h`
    (history), `l R` `l S` (persist), `M-p` `M-n` (recall), `s o`
    (formulas)

* profile:vim
  Vim's navigation keys over maf's commands — not vim's command model.
  The profile *derives from native* (2026-08-21: `:derive 'native` in
  src/bindings.el, resolved at every compile — see
  `maf-bindings--effective-defaults'): native's whole layout — the
  mafcmd table, shadowing, additions — flows through with no
  declaration naming vim, and vim's own claims displace whatever they
  overlap, so a motion on j drops the inherited j family whole. Base
  remaps, module keys, and digit entry reach vim on their own paths,
  as they always did. What the motions displace still needs relocated
  homes — families keep their second letters when they move, so they
  relocate whole.
** motions (decided 2026-08-20, implemented in src/bindings.el)
   The split mirrors vim's own: fine motion on h/l, vertical on j/k,
   structural motion on w/b. Each key does what its Emacs cousin does
   — no new motion commands were needed.
   - [X] `h` / `l` — backward-char / forward-char (C-b / C-f). By
     char, not noun: noun-stepping is w/b's job, exactly vim's
     h-versus-w distinction
   - [X] `j` / `k` — next-line / previous-line (C-n / C-p). By line,
     not entry: the earlier by-entry proposal (a maf-entry-down/up
     pair) was passed over for the plain line motion — entries are
     one line in the common case, and line motion also walks the rows
     of a matrix or Big rendering
   - [X] `w` / `b` — maf-forward-noun / maf-backward-noun: the M-f /
     M-b motions on vim's word keys (M-f / M-b stay bound too)
   - [X] `x` — maf-del, C-d's command: vim's delete reflex
     (2026-08-21). The displaced single-key expand moves up a case to
     `X`, whose inherited resident mafcmd-log-exp cedes it (rehomed
     on the family's `o e`); expand's table key `a x` stays too
   - [X] `$` — maf-end-of-line-bounce (2026-08-21): to the end of the
     line, and from the end a bounce to the entry's start, M-m's
     landing. Shadows the $-seeded algebraic entry, which ' still
     opens
   - [X] `M-o` — mafcmd-float-frac (2026-08-21): the toggle's single
     chord, meta of the family's letter, tappable in a hold the way
     native's l l is — its only vim home, the mirror skipping l l.
     Displaces the inherited mod-360, which rides the family
     instead: `o w`, wrapping the angle into range (`l w` through the
     mirror)
   - already vim-shaped for free: `G` is maf-go-home in native
   - deliberately no `0` / `$` / `gg`: digits are digit-entry
     starters, $ is auto-algebraic entry, g is reserved for the
     plotting module; M-m stays beginning-of-entry

* free and weak keys (native)
  Candidate homes for future single-key bindings, generated against
  native's compiled map plus calc's own (2026-08-19). "Weak" = bound to
  something rarely pressed; the cost of taking it is noted. Sorted by
  priority: single letters, then capitals, then punctuation, then
  modified keys.
** single letters
   - `w` — calc-why: its information arrives by itself via
     calc-auto-why, and M-x calc-why remains. The cheapest key in the
     buffer; every other lowercase letter is a live prefix family or a
     real command
   - `y` — calc-copy-to-buffer: niche (yank result into another
     buffer), but no reflex replacement exists. Second choice
   - `g` — calc's graph prefix: weak today, but the plotting module
     (later::plotting in maf.org) will want it. Do not spend
   - reserved, never take: `z` / `Z` (calc's user-definition prefixes),
     `q` (quit is a reflex), `h` (help family)
** capitals
   - none free. `W` was the last one and mafcmd-sqr took it
   - `K` — calc-keep-args: weak-ish, but it is a fancy prefix that
     chains with maf's own M flag (a carrier in maf--map-flag-carriers)
     — take only with that machinery adjusted
   - `Y` — calc reserves it for users; not maf's to spend
** punctuation
   - `{` / `}` — calc-scroll-down/up: C-v / M-v cover scrolling; same
     trade already made when < > took calc's horizontal pair
   - `~` — calc-num-prefix: near-free, but a stretch to reach —
     fine for something occasional, wrong for a repeat-heavy command
   - `:` — calc-fdiv: moderate — fraction division is real but the
     fraction is also typed in digit entry (1 : 3). Cautious
   - not weak, despite looks: `;` (calc-semi, matrix entry punctuation
     — the [ ] lesson)
** modified keys
   - free meta: `M-a` `M-d` `M-e` `M-g` `M-j` `M-q` `M-t` `M-z`,
     and `M-r` since poly-roots moved to l t (2026-08-20; `M-h` went
     to the history the same day)
   - cautious meta: `M-v` (scrolling's other half), `M-y` (yank-pop
     pairs with maf-yank's C-y); never `M-x`
   - free-ish control: `C-z` (suspend, commonly rebound anyway); `C-t`
     was one until maf-swap-up took it as a second key (2026-08-20);
     cautious: `C-l`
     (recenter), `C-q` (quoted-insert), `C-r` / `C-s` (isearch over the
     stack is real), `C-j` (calc-over — an RPN staple, weak only for
     algebraic-entry users)
   - never: `C-a/b/e/f/n/p` (cursor motion the stack buffer lives on),
     bare `C-c` (mode-prefix convention — though `C-c C-<letter>` is
     the mode's own slice of it, which is how `C-c C-c` went to the
     simplify), `C-g` `C-u` `C-h` `C-x`
